# فرایند به‌روزرسانی، پشتیبان‌گیری و بازگشت

## ۱. «قابل‌به‌روزرسانی» در این پروژه یعنی چه
نسخهٔ جدید قالب `dadvar` و افزونهٔ `dadvar-core` روی نسخهٔ قبلی نصب می‌شود و **محتوا، تنظیمات، منوها، تنظیمات سفارشی‌سازی و صفحه‌های المنتور حفظ می‌شوند**، چون همهٔ این‌ها در پایگاه داده‌اند و در فایل‌های قالب/افزونه نیستند. این موضوع روی یک نصب تازه آزمایش شده است (docs/test-report.md، بخش «ارتقا و بازگشت»).

**به‌روزرسانی خودکار ساخته نشده است.** وردپرس برای این قالب و افزونه اعلان به‌روزرسانی نشان نمی‌دهد؛ نسخهٔ جدید به‌صورت فایل ZIP تحویل و دستی نصب می‌شود. (به‌روزرسانی خودکارِ خود وردپرس و المنتور جداست و مثل همیشه کار می‌کند.)

## ۲. نسخه‌گذاری
- شمارهٔ نسخه در `style.css` (قالب) و `dadvar-core.php` (افزونه): `اصلی.فرعی.اصلاحی` مثل `1.0.1`.
- هر تغییر در `CHANGELOG.md` همان بسته ثبت می‌شود.
- تغییر ساختار داده فقط با یک گام مهاجرت تازه در `class-migrations.php` (افزایش `VERSION`)؛ گام‌ها تکرارپذیرند و داده‌ای حذف/بازنویسی نمی‌کنند.
- شخصی‌سازی کدی فقط در قالب فرزند `dadvar-child`؛ هرگز فایل‌های قالب اصلی یا افزونه را مستقیم ویرایش نکنید (با به‌روزرسانی پاک می‌شوند).

## ۳. پشتیبان‌گیری (قبل از هر به‌روزرسانی)
پشتیبان دو بخش دارد و **هر دو** لازم است:
1. **پایگاه داده** (محتوا، تنظیمات، صفحه‌های المنتور، درخواست‌ها): از پنل هاست (phpMyAdmin ← Export) یا افزونهٔ پشتیبان، یا `wp db export backup-YYYYMMDD.sql`.
2. **فایل‌ها**: دست‌کم پوشهٔ `wp-content` (تصاویر بارگذاری‌شده، قالب‌ها، افزونه‌ها).

فایل پشتیبان را بیرون از هاست هم نگه دارید. پشتیبان شامل اطلاعات شخصی درخواست‌کنندگان است؛ جای امن نگهداری شود.

## ۴. نصب نسخهٔ جدید
1. **اول روی نسخهٔ آزمایشی (Staging)**: نسخهٔ آزمایشی را از پشتیبان روز سایت اصلی بسازید.
2. پشتیبان کامل (بخش ۳).
3. پوسته‌ها ← افزودن ← بارگذاری ← `dadvar-X.Y.Z.zip` ← «جایگزینی نسخهٔ فعلی با نسخهٔ بارگذاری‌شده».
4. افزونه‌ها ← افزودن ← بارگذاری ← `dadvar-core-X.Y.Z.zip` ← «جایگزینی نسخهٔ فعلی…».
5. اگر یادداشت نسخه گفته مهاجرت دارد، کافی است یک صفحهٔ پیشخوان را باز کنید (خودکار اجرا می‌شود) یا `wp dadvar migrate`.
6. اگر المنتور استفاده می‌شود: المنتور ← ابزارها ← «بازسازی فایل‌ها و داده‌ها».
7. بررسی سریع: خانه، یک خدمت، یک مقاله، تماس (ارسال یک فرم آزمایشی)، منوی موبایل، جست‌وجو.
8. فقط پس از تأیید روی Staging، همین مراحل روی سایت اصلی.

با WP-CLI:
```
wp db export before-update.sql
wp theme install dadvar-X.Y.Z.zip --force
wp plugin install dadvar-core-X.Y.Z.zip --force
wp dadvar migrate
```

## ۵. بازگشت به نسخهٔ قبلی
- **فقط فایل‌ها:** ZIP نسخهٔ قبلی را به همان روش «جایگزینی» نصب کنید. این کار برای مشکل ظاهری یا کدی کافی است.
- **⚠️ بازگشت فایل‌ها، تغییرات پایگاه داده را برنمی‌گرداند.** اگر نسخهٔ جدید مهاجرت داده داشته، علاوه بر فایل‌ها پایگاه داده را هم از پشتیبانِ پیش از به‌روزرسانی بازگردانید (`wp db import before-update.sql` یا Import در phpMyAdmin). توجه: هر محتوا یا درخواستی که **بعد** از پشتیبان ثبت شده با این کار از بین می‌رود؛ پیش از بازگردانی از وضعیت فعلی هم یک پشتیبان جدا بگیرید.
- نسخهٔ ۱٫۰٫۰ هیچ مهاجرتی جز گام ۱ ندارد.

## ۶. بازیابی کامل از پشتیبان (سایت از دست رفته)
1. وردپرس هم‌نسخه را نصب کنید (یا فایل‌های پشتیبان را بازگردانید).
2. پوشهٔ `wp-content` پشتیبان را جایگزین کنید.
3. پایگاه داده را Import کنید و در `wp-config.php` اطلاعات اتصال را تنظیم کنید.
4. اگر دامنه عوض شده: `wp search-replace 'https://old' 'https://new' --all-tables`.
5. «تنظیمات ← پیوندهای یکتا ← ذخیره» و در المنتور «بازسازی فایل‌ها».

این روند (خروجی پایگاه داده ← حذف تصادفی ← بازگردانی) روی محیط آزمایشی اجرا و تأیید شده است.

## ۷. ساخت بسته‌ها از کد منبع
```
cd wp-law-site
scripts/build.sh            # خروجی: dist/*.zip و dist/SHA256SUMS.txt
```
پیش از ساخت، نسخه را در `style.css` و `dadvar-core.php` (هر دو محل: سربرگ و `DADVAR_CORE_VERSION`) افزایش دهید و CHANGELOG را به‌روز کنید.
